### 4.6 Form, fallback and failure behaviour

- The form posts to `/api/enquiries.php`, never reports success without `201` + a 32-hex reference, and
  has explicit pending, success and error states (`ref-about.jsx:289-341`).
- A stable `requestId` makes retries idempotent; the same unchanged payload is resent on retry. A 409,
  422, 429 or 503 produces a specific message; a timeout produces "we could not confirm whether your
  enquiry was saved" rather than a false success.
- With JavaScript disabled, the form is hidden by the global `<noscript>` rule and a **visible direct
  email fallback** appears in the left column (`ref-about.jsx:440-448`), tested at 390 px in
  `seo-browser.test.mjs`. Previous behaviour hid the form with no visible alternative.
- Server validation: name 1–120, email ≤190 + `FILTER_VALIDATE_EMAIL`, type allow-list, message
  20–10,000, consent must be `true`, honeypot must be empty, unexpected fields rejected, UUID
  `requestId` (`enquiry-store.php:57-67`). Rate limit is 5/IP/hour (`:99`). The enquiry and the
  owner/ack outbox rows are inserted atomically (`:101-104`). The mail worker remains **dry-run** until
  SMTP credentials are supplied.

### 4.7 Privacy accuracy

The privacy page now matches the implementation:

- first-party `/api/track.php`, DNT/GPC opt-out, sessionStorage session ID, daily HMAC visitor hash,

## 7. Privacy and security findings

### 7.1 What was verified

- **Analytics** (`api/track.php`): DNT/GPC is enforced before the beacon loads; a 32-hex session ID lives
  in sessionStorage; the visitor key is a daily HMAC of IP + UA (`track.php:101`); the raw IP is not
  stored; there is a 120 events/minute per-visitor cap; raw events are pruned after 180 days
  (`track.php:129`); daily aggregates carry no visitor identity. No public-site cookies.
- **Enquiries** (`api/enquiry-store.php`): strict field allow-list, type allow-list, consent boolean,
  honeypot, UUID request ID, payload-hash idempotency, 5/IP/hour, atomic enquiry + outbox insert. The
  IP is stored only as a keyed hash. The mail worker is dry-run until SMTP credentials are provided.
- **Admin**: login throttling is shared across HTML and JSON endpoints; cookies are HttpOnly,
  SameSite=Lax, Secure over HTTPS; CSRF is session-bound; subscriber deletion requires CSRF; first-admin
  creation is CLI-only.
- **Files**: `api/config.php`, `*.sql` and `*.sample.php` are denied by `api/.htaccess`; `/scripts/` is
  denied by the root `.htaccess` (`:62`); SPA rewrites bypass `/admin` and `/api` (`:56-59`). Local
  checks: `/scripts/capture-evidence.mjs` → 403; `/api/config.php` → 404. No secret is committed; the
  deploy package excludes `api/config.php` and `.env`.

### 7.2 Headers

Both local and live send `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
`Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/microphone/geolocation/
interest-cohort disabled), and `Cache-Control: no-cache, no-store, must-revalidate` for HTML. Live adds
`content-security-policy: upgrade-insecure-requests` at the CDN.

**Missing hardening:** no `Strict-Transport-Security` and no substantive Content-Security-Policy. These
are recommended follow-ups *after* inventorying the inline boot script/styles and confirming HTTPS-only
behaviour at the CDN. `X-XSS-Protection` is legacy and can be dropped. The local harness also serves
`/admin/` as 404 because admin files are excluded from the public deploy; that is expected.

### 7.3 Open security/privacy questions

1. **Client IP behind Hostinger CDN.** `bootstrap.php:89` deliberately trusts only `REMOTE_ADDR` and
   ignores forwarded headers (good against spoofing). If `hcdn` terminates connections and does not pass
   the visitor IP as `REMOTE_ADDR`, then rate limits and the daily visitor hash see the CDN edge. Verify
   at the origin after deployment; if needed, trust one documented Hostinger header only after
   validation, and document the change. Until then, treat unique-visitor counts as approximate.
2. **Retention is opportunistic.** The 180-day prune runs inside beacon writes, 5,000 rows per request.
   With little traffic, old rows can persist beyond 180 days. A scheduled maintenance job would make the
   privacy wording exact.
3. **SMTP not exercised.** No real mail has been sent; the outbox is durable but delivery is unverified.
4. **No HSTS/CSP** (see above).
